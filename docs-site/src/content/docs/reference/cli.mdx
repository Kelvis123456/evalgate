evalgate has two commands, `run` and `baseline`. You can invoke it as `evalgate` (the console script installed by pip) or `python -m evalgate`. The two behave the same except for one import-path detail, see [Plug in your own app](/guides/own-app/).

```text title="evalgate --help"
usage: evalgate [-h] [--version] {run,baseline} ...

CI ship gate for RAG and LLM apps.

positional arguments:
  {run,baseline}
    run           run the eval set and gate against the baseline
    baseline      run the eval set and write a new baseline

options:
  -h, --help      show this help message and exit
  --version       show program's version number and exit
```

`evalgate --version` prints `evalgate 0.1.0`. A command is required. Running `evalgate` alone prints a usage error and exits `2`.

## `evalgate run`

Run the eval set against the app, compare to the baseline, print the report.

```text title="evalgate run --help"
usage: evalgate run [-h] [--evalset EVALSET] [--baseline BASELINE] [--app APP]
                    [--param KEY=VALUE] [--tolerance TOLERANCE]
                    [--report-file REPORT_FILE]

options:
  -h, --help            show this help message and exit
  --evalset EVALSET
  --baseline BASELINE
  --app APP             module:factory (default: reference app)
  --param KEY=VALUE     keyword argument for the app factory, repeatable
  --tolerance TOLERANCE
                        override every tolerance in the baseline
  --report-file REPORT_FILE
                        also write the Markdown report here
```

| Flag                   | Default                 | Behaviour                                                                                                                                                                                  |
| ---------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `--evalset PATH`       | `evals/questions.jsonl` | The [eval set](/concepts/eval-set/). Relative to the current directory.                                                                                                                    |
| `--baseline PATH`      | `baseline.json`         | The [baseline](/concepts/baseline-and-tolerance/) to compare against. Missing file exits `2`.                                                                                              |
| `--app MODULE:FACTORY` | `evalgate.refapp:build` | The app factory, see [Plug in your own app](/guides/own-app/).                                                                                                                             |
| `--param KEY=VALUE`    | none                    | Keyword argument passed to the factory. Repeatable. Values become `int`, then `float`, then `true`/`false` booleans, else stay strings. A pair without `=` or with an empty key exits `2`. |
| `--tolerance X`        | from the baseline       | A float that replaces every tolerance, including per-metric values. Negative exits `2`. A non-number is rejected by argument parsing, also exit `2`.                                       |
| `--report-file PATH`   | none                    | Also write the Markdown report to this path, as UTF-8. The report still goes to stdout.                                                                                                    |

`run` reads `k` from the baseline (default `3`), so `hit_at_k` is computed with the same `k` the baseline used.

Exit codes: `0` pass, `1` regression, `2` bad input. See [Exit codes](/concepts/exit-codes/).

## `evalgate baseline`

Run the eval set and write a new baseline.

```text title="evalgate baseline --help"
usage: evalgate baseline [-h] [--evalset EVALSET] [--baseline BASELINE]
                         [--app APP] [--param KEY=VALUE]

options:
  -h, --help           show this help message and exit
  --evalset EVALSET
  --baseline BASELINE
  --app APP            module:factory (default: reference app)
  --param KEY=VALUE    keyword argument for the app factory, repeatable
```

`--evalset`, `--baseline`, `--app` and `--param` have the same meaning and defaults as in `run`. Here `--baseline` is the file that gets written. On success it prints `wrote <path>` and exits `0`. It writes `k` as `3`, the default tolerance as `0.02` and an empty `tolerances` object every time, discarding any values already in the file. See [Update the baseline](/guides/update-baseline/).

`baseline` has no `--tolerance` and no `--report-file`.

## Environment

| Variable         | Effect                                                                                                                                                                        |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `EVALGATE_JUDGE` | `module:factory`. When set, loads a judge and adds a `judge_score` metric to the run. Read by both commands. Unset by default. See [Metrics](/concepts/metrics/#judge_score). |

## Output streams

- The report goes to **stdout**.
- Errors go to **stderr** as `evalgate: error: <message>`.
- `baseline` prints a single `wrote <path>` line to stdout.
